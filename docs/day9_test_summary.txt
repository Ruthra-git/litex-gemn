4. OBSERVED TOOLCHAIN / SIMULATOR LIMITATION
--------------------------------------------
In the captured runs, after Cocotb printed the completed test summary showing
PASS counts equal to the total test count and FAIL=0, the simulator process
terminated with:

    Segmentation fault (core dumped)

The failure occurred after the final test-summary output, not during the listed
functional tests. The Make target then returned a non-zero exit status and
removed results.xml.

Observed versions/context from the logs:
- Cocotb: 2.1.0 development build
- Icarus Verilog: 14.0 development build
- Python interpreter used by Cocotb: 3.11.6 (OSS CAD Suite bundled interpreter)
- Simulator: Icarus Verilog with Cocotb VPI integration

The post-summary segmentation fault is treated as a simulator/VPI/toolchain
shutdown issue pending further investigation. The available logs do not establish
its precise root cause. It must not be represented as an RTL functional failure,
but it also means the simulator process did not exit cleanly and XML result-file
completion was not reliable for these runs.

5. KNOWN LIMITATION / VERIFICATION STATUS
-----------------------------------------
STATUS: FUNCTIONAL REGRESSION PASS — TOOLCHAIN EXIT/SHUTDOWN ISSUE OBSERVED

- All nine DUT/lane configurations reached the final Cocotb test summary.
- All 99 test executions reported PASS.
- No functional test failures were reported.
- The simulator subsequently segfaulted after the summary in the captured runs.
- results.xml was deleted by the Make flow following the abnormal simulator exit.
- Therefore, functional results are documented from the terminal summaries;

This limitation should be retained in the verification record until the simulator,
Cocotb/VPI environment, or shutdown behavior is corrected and the regression is
re-run with clean process exits and valid result XML files.
